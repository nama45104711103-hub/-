# このリポジトリのセキュリティ確認項目

個人開発のWebアプリ（Next.js / TypeScript / Vercel / Supabase）で実際に事故が起きやすい箇所のみを挙げる。
一般的な脆弱性の確認は標準のチェックに任せ、ここには構成固有の項目だけを書く。

## 秘密情報の置き場所

- APIキー、トークン、接続文字列をソースコードに直接書かない。
- `NEXT_PUBLIC_` で始まる環境変数はブラウザに送られる。秘密情報にこの接頭辞を付けない。
- 外部APIの呼び出しにキーが必要な場合、ブラウザ側のコンポーネントから直接呼ばず、Route Handler（サーバー側）を経由させる。
- `.env.local` が `.gitignore` に入っていることを確認する。

## Supabaseを使う場合

- テーブルを作ったら、必ず行レベルセキュリティ（Row Level Security）を有効にする。有効にしていないテーブルは、キーを持つ誰からでも全行が読める。
- service_role キーをブラウザ側のコードに置かない。サーバー側だけで使う。
- クライアント側のクエリが、ログインユーザー本人のデータだけを返す条件になっているか確認する。

## 入力の扱い

- ユーザーが入力した文字列を `dangerouslySetInnerHTML` に渡さない。
- URLパラメータやフォームの値を、検証せずに数値計算や外部リクエストに使わない。空文字、負の数、極端に大きい数を入れても落ちないこと。
- ユーザーが入力したURLにサーバー側からアクセスする処理を作らない。必要な場合は接続先を固定のリストに限定する。

## 公開前

- ソースコードに個人情報、実在のメールアドレス、テスト用のパスワードが残っていないか確認する。
- デバッグ用に作った、認証を通さずデータを操作できるエンドポイントが残っていないか確認する。
- `console.log` に秘密情報や個人情報を出力していないか確認する。
